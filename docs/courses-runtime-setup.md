## Owner-confirmed payment table initialization

After explicit production setup approval, the hosting operator can temporarily set `ASCORE_ALLOW_PAYMENT_SCHEMA_SETUP=1`, keeping `ASCORE_ENABLE_PAID_COURSES=0` and `ASCORE_ENABLE_FREE_COURSES=0`, then restart the pushed Git release. As the existing `aswinfrn` administrator, open Course orders → Nomod connection status → Initialize payment tables. Read and confirm the four-table scope. The action requires existing session, exact origin, CSRF, verified database identity/core ownership, and accepts only an empty request body. It creates only `course_paid_orders`, `course_paid_downloads`, `course_payment_events` and `course_payment_limits`, with `ascore-payments` ownership markers. Review the Verified result, restore the temporary flag to `0` and restart. Do not repeat the already completed course-order initialization. This action makes no provider request, charge, email, private PDF installation or public gate change. Interrupted DDL remains auditable and needs readiness review before a deliberate retry. The existing protected action removes the requirement to run a CLI on managed hosting.
