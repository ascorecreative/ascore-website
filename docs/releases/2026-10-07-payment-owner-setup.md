# Protected payment-table setup

The existing Course orders page now offers Initialize payment tables under Nomod connection status when the four optional payment tables are unverified. This removes the managed-hosting CLI requirement. POST `/api/courses/admin/payments/setup` requires the existing authenticated aswinfrn admin, exact application origin, session CSRF, temporary `ASCORE_ALLOW_PAYMENT_SCHEMA_SETUP=1`, paid/free checkout disabled, and verified MariaDB database/core ownership. The body must be empty; no SQL, paths or configuration can be submitted.

Before writes the action rechecks the selected database identity, engine, dedicated inventory and platform marker. The existing fixed migration creates only course_paid_orders, course_paid_downloads, course_payment_events and course_payment_limits. Existing unowned conflicts are refused. Ownership markers identify an incomplete/complete migration. An in-process claim coalesces concurrent clicks; repeat verified setup performs no DDL. Interrupted DDL is marked for review rather than hidden; an explicitly approved retry can complete owned partial tables. Start/completion/review actions are audited. Runtime payment-schema readiness updates after verification; all other activation requirements remain closed. Production startup remains read-only.

The browser presents a scope-specific confirmation before its empty, CSRF-protected POST. Cancel sends no mutation. After success it instructs the operator to restore the temporary flag to 0 and restart. Production DDL requires the user's clear confirmation; no production setup was executed during implementation. No credentials, provider request, charge, email or full paid PDF was used or released.

Build and lint pass with the three existing lint warnings.
