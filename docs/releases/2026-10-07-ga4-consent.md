# GA4 with public-route consent

GA4 measurement ID **G-MX800C01N9** is integrated into the existing marketing controller, alongside Meta Pixel **1058485446949199**. The owner explicitly confirmed that Enhanced Measurement was turned off in the Google web stream on 2026-10-06. Keep it off: Google documents that history-based pageviews can still be sent with `send_page_view:false` when that account setting is enabled. No Google Analytics account setting was changed by the agent.

Consent storage is now version 2. The choice names both Google Analytics and Meta Pixel, offers equal allow/deny buttons, and can be reopened through Measurement settings. An old Meta-only version 1 grant does not authorize the expanded collection. Unknown/denied choices, expired or malformed stored choices, Global Privacy Control and Do Not Track prevent loading either SDK. The Google SDK is async and only requested after an eligible public-route opt-in; there is no Google preconnect or unconditional tag. The locally served controller remains approximately 4.3 KB gzipped; the external Google SDK is not on the initial page-load path before consent.

Google starts with all four consent types denied. Only analytics_storage is granted on consent; Google advertising storage, advertising user data and advertising personalization stay denied. Google signals and ad-personalization signals are disabled. Config runs once per document with automatic initial pageviews disabled; the existing public-route observer sends one manual page_view per actual public path. Hash-only changes and repeated pageshow do not create extra views. Public-page metadata uses allowlisted paths and fixed titles, with query strings, fragments and referrers removed. This intentionally omits campaign query/referrer attribution from the GA4 payload. There are no user_id, user_data, form-field or customer-email parameters.

Portal/auth/unknown routes, private hashes, sensitive query URLs and sensitive same-origin referrers are excluded. On becoming ineligible or withdrawing consent, Google collection is disabled with its per-measurement-ID opt-out flag and analytics consent is denied. Pending receipts are cleared on withdrawal/private-route transitions. The SDK is never configured if consent is withdrawn while its download is pending. Google and Meta load/event queues are independent, so one blocked provider does not prevent the other from working.

Purchase uses the existing server-confirmed paid receipt hook after checkout has validated its paid-readiness gate and removed the return URL's sensitive query. The receipt must have paid status, AED currency, unique known course items and the exact 4,999-fils price per item. Pending/authorised states, a return URL alone, mismatched receipt IDs, wrong totals and closed checkout gates do not produce a purchase. GA4 receives only the opaque server-derived paymentEventId as transaction_id, catalog IDs/titles and AED 49.99 / 99.98 values. Order IDs, emails, receipt capabilities and PDF tokens are not copied. A separate bounded 30-day sent-ID ledger and in-memory set suppress repeats independently of Meta; transaction_id supplies a stable identity for Google-side deduplication. This browser ledger is bounded and not proof of actual Google receipt.

Validation: build/prerender/precompression succeeds; lint retains only the same three pre-existing warnings; all **84** backend tests pass. The existing consent/Meta/course sweep passes **16** route/viewport combinations (320/390/768/1440), cart totals, private-route exclusions, purchase negatives and persistent sticky controls without consent overlap. New Google checks cover old consent, privacy signals, sensitive query/referrer, script-load revocation, cross-tab withdrawal, SDK blocking, malformed receipts and reload deduplication. The downloaded public Google SDK was also executed in isolated headless Chrome with every collection request fulfilled locally: exactly three intended public pageviews and one fixture purchase, no extra private-route/withdrawal traffic, no customer/order/capability fields. **Zero analytics collection requests were sent to Google or Meta, zero backend mutations, zero real purchases or emails.** Evidence: `2026-10-07-ga4-browser.json` and `2026-10-07-ga4-course-layouts.json`.
