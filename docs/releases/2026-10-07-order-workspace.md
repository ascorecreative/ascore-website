# Orders, customers, traffic charts and checkout

Orders now sits directly below Home. Order previews open a dedicated URL-backed screen with payment, email, download usage, internal timeline entries and editable tags. Customers derives real guest profiles and exact confirmed totals from the customer ledger, excluding private probes. Existing saved names are used before a missing-name label; admins can correct the customer profile. New browser checkout asks for name and email, then replaces that form with the payment continuation panel. Secure checkout information is below the compact order summary.

Order tags are searchable across the full ledger and names propagate to order previews. Notes append rather than overwrite; tag/profile edits use revision checks to reject stale saves. All management endpoints require the existing agency session and mutations retain Origin and CSRF checks. They expose no payment, receipt or download capabilities and cannot mark an order paid, charge, email or refund. SMTP acceptance is displayed as Email sent, with inbox delivery explicitly unconfirmed.

Three additive tables (course_customers, course_order_metadata, course_order_entries) are initialized only by the existing authenticated owner using Enable order management. MariaDB setup verifies dedicated database identity and application ownership, writes a resumable ownership marker before DDL, and verifies completion. No existing tables, orders, prices, credentials or unrelated source changes are altered. Startup accepts the optional owned schema before and after setup.

GA4 charts use read-only runReport date, deviceCategory and country dimensions with sessions, activeUsers and screenPageViews. Daily values, source/device/country donut legends and underlying tables expose actual data and empty/error states. Chart failures preserve separately fetched totals. Google documentation: https://developers.google.com/analytics/devguides/reporting/data/v1/api-schema and https://developers.google.com/analytics/devguides/reporting/data/v1/rest/v1beta/properties/runReport .

The owner supplied 36 previous-website Meta Ads reviews. Author, rating and text are preserved; historical relative dates are omitted because extraction time is unknown. They are labelled previous Ascore website and do not receive a verified-purchase label. The Practical AI course receives none of these Meta-specific testimonials. Reviews from earlier editions are identified alongside the current course/support details.

Validation: 136 backend tests pass, including real HTTP authorization/CSRF, persistence, full-ledger filtering, customer exclusion/totals, stale edits and no payment-row changes. Lint has only the existing three warnings. Build, prerender, compression and diff checks pass. Isolated actual local API browser checks cover note/tag/profile saves, detail refresh URLs, customer navigation, all 36 reviews and checkout review/edit transformation. Responsive 390px checks confirm no horizontal overflow and name/email preceding the summary. No payment, checkout or outgoing email was created during QA.
