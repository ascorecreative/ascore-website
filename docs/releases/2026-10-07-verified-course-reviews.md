# Verified course-buyer reviews

The user-approved Leave a review form accepts an actual paid buyer's course-specific review capability, a display name, rating 1–5, 20–2,000 characters and explicit publication consent. The capability is supplied only with an authenticated paid receipt and is distinct from receipt, download and conversion identities. The successful paid-return flow saves it for that course in the purchaser's browser; review eligibility does not expire with the PDF link. Pending/authorised/refunded/review-held orders, another course, invalid credentials and unsolicited fields cannot submit. Only one review per purchaser email/course is stored, including duplicate purchases. Input is rendered as plain text.

Submissions enter **pending**. The authenticated agency Course orders page includes moderation and accepts only Publish/Reject state changes. Existing origin, admin-role and CSRF checks protect mutation endpoints. Every submission and moderation has an audit record. The public API and rating count/mean include only published reviews whose purchase remains paid; a refund/review hold removes them from the aggregate. Stars, counts and Product aggregate-rating data render only when actual published API feedback exists. No disputed testimonial was seeded. No review request/reminder email or automation was created.

The normal production startup performs read-only schema checks, not migrations. Review submissions stay disabled by default with `ASCORE_ENABLE_COURSE_REVIEWS=0`. The source includes the protected setup action `POST /api/courses/admin/reviews/schema`, shown in the existing admin workspace. It requires aswinfrn, existing session/origin/CSRF, the temporary operator flag `ASCORE_ALLOW_REVIEW_SCHEMA_SETUP=1`, approved MariaDB identity/platform schema, separately verified payment-table ownership, and disabled paid/free checkout. It creates only `course_reviews` and `course_review_limits` with ownership markers `ascore-course-reviews` version 0/1, refuses unowned conflicts and supports an owned partial retry. No production setup was executed.

Owner activation order: verify the separate payment schema first; authorize/set the temporary review setup flag; redeploy the Git branch; use Initialize review storage once as aswinfrn; restore the setup flag to 0; enable the separate public-review flag only after verified eligibility/storage checks. These steps do not authorize enabling payments, PDF delivery, SMTP sends, Friday emails or advertisements. With no actual eligible paid orders, the form does not accept reviews. The course UI honestly shows preparation status while storage/submissions are closed.

Validation: build and lint succeed with the three pre-existing lint warnings; all 63 backend tests pass. Tests prove disabled defaults, private capability/paid-course eligibility, input rejection, persistent duplicates, moderation role/origin/CSRF, text safety, audit records and aggregate removal after refund. Eight public review-form viewport/readiness fixtures (320/390/768/1440) and the existing admin dashboard regression pass. The Pixel, header, cart, price, assets and no-real-Meta-event suite also passes. All browser submissions and backend payment/email fixtures are isolated synthetic tests, not public feedback or production orders.

These are controlled local measurements, not production or physical-phone results. The existing eight-section admin regression and four-viewport Publish/Reject controls also pass.
