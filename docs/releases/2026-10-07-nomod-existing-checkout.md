The action needs the existing owner session, exact origin/CSRF, verified payment tables, saved Hosted Checkout key and closed paid/free checkout. No new flag or schema setup is required.

The server only GETs `https://api.nomod.com/v1/checkout/{id}` using its saved key. It rejects redirects, times out after 12 seconds and bounds the streaming response to 128 KB. Browser-supplied URL/host/key/configuration values are rejected. Concurrent reads are coalesced, results cached for 30 seconds and attempts limited to five per runtime hour; nothing retries in the background.

The private report checks matching session ID, authenticated key, paid checkout, AED currency, reference presence, unique UUID charges and captured totals matching the checkout. It returns only the parsed HTTPS hostname, without its path/query/capability. Only nomod.com or a subdomain is treated as Nomod-owned. That actual provider result supplies the exact hostname for NOMOD_CHECKOUT_HOSTS; this release does not guess or configure one. It also reads the existing signature-verified webhook ledger to check for a matching charge.completed charge ID. Customer data, raw provider payload, credentials, checkout/charge IDs and internal references are excluded from the response.

The diagnostic writes no financial/audit rows, schema or configuration. It creates no checkout, charge/refund, email, PDF download or advertising purchase. Contract approval and public checkout stay closed until the actual paid response and matching signed Hosted Checkout event have been reviewed.
